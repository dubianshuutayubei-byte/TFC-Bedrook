## 対象範囲

今回の実装対象は、開発工程1〜7の基盤と、工程7〜8に配置した地形生成の事前設計・数値プロトタイプ。ここで「基盤あり」とするものは、純粋関数・データ定義・保存形式が存在する状態を指し、Minecraft内の完成機能とは区別する。

## 追加したコード・データ

### ランタイム・状態
- `scripts/main.js`：プレイヤー参加時に状態データを初期化/同期し、200tickごとにオンラインプレイヤーの水分・栄養を更新。開発用Script EventでUIを開く。
- `player-state-service.mjs`：水分・5系統栄養の状態生成、更新、JSON保存・復元、プレイ中の時間経過による減少。
- `state-clock.mjs`：経過時間と間隔実行の純粋関数。

### 生存・加工
- `agriculture-service.mjs`：土壌水分・N/P/K、作物環境判定、肥料、成長段階。
- `food-service.mjs`：鮮度、温度依存腐敗、保存方法、摂取反映。
- `fauna-service.mjs`：動物状態、気候・地形適合、給餌、成長、繁殖条件。
- `processing-service.mjs`：工程レシピ検証、入力・温度・設備条件、進行率。
- `item-catalog.json` / `processing-recipes.json`：内部IDと初期工程レシピ。

### 自然環境
- `geology-service.mjs`：深度別岩石層選択、鉱脈調査の判定、地形区分。
- `terrain-profile-service.mjs`：固定seedの滑らかな多段階Value Noise試作。大陸性・山稜・谷・河川マスク・起伏を別フィールドとして算出。
- `terrain-profile.json`：大陸/山岳/局所/谷/河川のスケールと強度を分離した調整値。
- `crops.json` / `fauna.json` / `geology-profiles.json`：初期データセット。

## 重要な制約・未検証点

1. 現在の地形プロファイルは、座標を使った決定論的な設計用サンプラーであり、Minecraftの地形生成エンジンを置き換えない。滑らかな連続フィールドと河川/谷のマスク値を計算する段階で、水ブロック配置・河道掘削・流域連結・火山・海溝の生成は未実装。
2. 内部IDカタログは、Bedrockに登録済みのアイテム・ブロック一覧ではない。未登録IDをゲーム内レシピで使用しない。
3. 加工レシピの一部時間・数量は仮置き。TFC公式データで確定できていない数値を公式値として扱わない。
4. 食品腐敗の時間単位・保存倍率は仮のゲームバランス値。TFC実装と照合して確定する。
5. Dynamic Propertyの初期化・保存と、オンライン中のニーズ減少処理を追加したが、Minecraft 26.60実機でのロード・再参加・マルチプレイ動作は未確認。オフライン中の経過時間は計算しない。
6. 水分は1ゲーム日あたり18、各栄養値は1ゲーム日あたり2.4減少する仮バランス値。公式TFCの確定値ではなく、実機テスト後に調整する。
7. GitHub上の静的検査・Nodeテストは、Minecraft内のAPI・リソース・ワールド生成の検証を代替しない。

## 次の工程

- 地形参考資料を受け取り、地形生成の数値モデル・岩石層・気候・河川の仕様を確定する。

- 地形生成と独立に、アイテム・ブロック登録とRPテクスチャを進め、各サービスを実ゲームイベントへ接続する。
